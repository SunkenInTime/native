fix: **Less resident memory per app on Windows**: large fixed-capacity scratch no longer becomes resident before an app uses it. The capture and session-replay modes and the chrome display-list path no longer inline their ~650 KiB to ~1 MiB frames into the live run loop and `rebuild`; the display-list refresh and render-animation scratch moved from stack frames into the heap-allocated runtime and app; `Effects` and the virtual-extent tables initialize in place instead of copying their full default images; and three Windows host helpers no longer keep a 64 KiB path buffer on the stack. A Weaver widget drops from 11.4 MiB to 9.2 MiB private working set, with resident stack down from 2.5 MiB to 0.86 MiB.
