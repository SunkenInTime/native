improvement: **Windows apps load Media Foundation, WinHTTP, SHELL32 and DirectComposition only when they use them**: the host no longer imports these DLLs statically, so an app that never plays audio, shows a tray icon or notification, opens a URL, receives a file drop or presents a GPU surface never maps them or their dependencies (Windows.Storage, MFCORE, RTWorkQ). In a Weaver host running ten clock widgets that is ten fewer modules and about 0.5 MiB less private working set; the first use costs 1–4 ms (Media Foundation 7–21 ms). A DLL that cannot load (for example Media Foundation on a Windows N edition without the Media Feature Pack) now fails only its feature, with a log line naming the feature, DLL, function and Windows error, instead of stopping the app from starting.
