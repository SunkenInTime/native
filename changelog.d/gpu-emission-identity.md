fix: **GPU surfaces no longer speed up after input on Windows**: moving the mouse over (or resizing) an animating shared-GPU surface re-armed its frame emission without cancelling the pending deadline timer or post, so both fired and each started a self-re-arming frame chain. A few mouse moves took a 60 fps canvas to ~900 fps and its process from ~2% to ~19% CPU, permanently. Each scheduled emission now carries an identity, superseded ones are cancelled where possible, and the window procedure only emits the one currently scheduled.
